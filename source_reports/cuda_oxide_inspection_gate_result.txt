Why we stop before writing the kernel

Architectural blocker, hard. Per direct source inspection:

┌──────────────────────────────────────────┬──────────────────────┐
│     cuda-oxide v0.1.0 MMA primitives     │     Target arch      │
├──────────────────────────────────────────┼──────────────────────┤

├──────────────────────────────────────────┼──────────────────────┤

├──────────────────────────────────────────┼──────────────────────┤

├──────────────────────────────────────────┼──────────────────────┤
│ cuda-device/src/cluster.rs               │ sm_90+               │

│ mma.sync / WMMA for Ampere (sm_80/sm_86) │ NONE                 │
└──────────────────────────────────────────┴──────────────────────┘

Pipeline feature detector confirms: None_default → sm_80 baseline means no tensor-core abstractions at all for Ampere. Marlin's whole advantage on RTX 3090 (sm_86) is sm_80 tensor cores via mma.sync.aligned.m16n8k16.f16. A cuda-oxide kernel today can only use CUDA cores → would land at 5-20× slower than Marlin, likely also slower than the bnb 55 t/s baseline.

The spec's stop_conditions includes: "stop production consideration if the candidate does not beat AWQ-Marlin under identical local workload measurements." — met before any line of kernel code.
